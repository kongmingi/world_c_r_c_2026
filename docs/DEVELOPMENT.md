# 개발 과정과 문제 해결

2026 WCRC 물류로봇2-분류(대학부) 출전 로봇의 소프트웨어 개발 기록입니다. 결과: **한국로봇교육콘텐츠협회장상**.

## 2. 설계 원칙

- **값과 코드 분리**: 거리·PSD 목표·팔 자세·속도·카메라 범위 등 약 150개 값을 `Tuning.h` 한 파일에 모음. 현장에서 코드를 몰라도 숫자만 고칠 수 있게 함
- **측정한 값만 넣기**: 예시 코드 숫자는 그 로봇 기준. 로봇을 바른 위치에 놓고 직접 잰 값만 사용
- **한 번에 하나씩**: 한 번에 한 가지만 바꾸고 결과를 확인, 문제가 생기면 이전 버전 폴더로 즉시 되돌림
- **현장 도구 먼저**: 재업로드 없이 측정·시험할 수 있는 시리얼 명령을 먼저 만듦 ([CONSOLE.md](CONSOLE.md))

## 3. 핵심 문제와 해결

### ① 팔이 업로드할 때마다 다른 자세로 가는 문제
- **문제**: 같은 숫자를 넣어도 업로드마다 자세가 달라지고, 팔이 반대로 돌아 바닥에 부딪힘
- **원인**: 한 관절의 동작 범위가 모터 위치값 0/4095 경계를 가로지름. 일반 위치 모드는 경계를 넘지 못해 반대로 크게 회전. 업로드 시 보드만 리셋되고 모터 상태는 유지됨
- **해결**: 확장 위치 모드 + 관절별 범위(창) 기준으로 현재 위치를 다시 계산해 항상 가까운 방향으로 이동(`goal = raw + (target − ToWindow(raw))`). 위치 읽기 실패 시 이동 취소
- **결과**: 같은 숫자 = 같은 자세. 이후 모든 자세 튜닝의 기준이 됨

### ② 강사 예제 펌웨어 분석·복원
- **문제**: 받은 hex 펌웨어가 어떤 소스인지, EEPROM 자세 파일이 정상인지 알 수 없음
- **해결**: hex 안의 문자열·함수 호출 순서·상수(거리·PSD·관절 제한·배정표 바이트)를 소스와 하나씩 대조해 같은 소스임을 검증. EEPROM 파일이 부트로더 읽기 버그로 주소가 밀려 깨져 보인다는 점을 규명하고, 자세 백업·복구 스케치를 작성
- **결과**: 예제와 우리 코드의 차이를 근거를 가지고 비교 ([archive/INSTR](../archive/INSTR))

### ③ PSD 평탄 구간 때문에 1열 위치가 매번 달라지는 문제
- **문제**: 적재함 1열 정렬 후 카메라 중심 오차가 매번 달라짐
- **원인**: 기준으로 쓰던 측면 PSD 607/611이 센서 최고점 근처라 약 15mm를 움직여도 값이 거의 변하지 않음
- **해결**: 기울기가 큰 572 지점을 기준점으로 바꾸고, 벽 정렬 → 정해진 거리 이동 → 전방 PSD로 1열 정렬. 이후 모든 기준값은 ±5~20mm 움직여 값이 고르게 변하는지 확인한 뒤 사용
- **결과**: 1열 도착 위치 안정. `c1 N` 명령으로 어느 열에서든 1열 정렬 가능

### ④ 대회 1주 전 로봇 교체 → 전면 재보정
- **문제**: 같은 코드로 팔이 90° 돌아가고, 이동 중 바퀴에 걸림
- **원인**: 이전 로봇 값을 그대로 씀. 코드 안에 "집기 자세는 저장값 대신 특정 밑동 각도를 강제로 쓴다"는 숨은 규칙이 있었음
- **해결**: 숨은 규칙을 찾아 기준 각도를 새 로봇 값으로 바꾸고, 자세 이름과 Tuning 변수를 1:1로 정리. 구간마다 PSD 목표를 다시 측정 (예: 벽 비틀림 −15 → −3, 열 비틀림 −5/−11 → −3/−3, 카메라 중심 x 185/182/177 → 150/169/168)
- **결과**: 대회 전 4일 안에 전 경로를 새 로봇에 맞춤

### ⑤ PSD 정렬이 목표 전에 멈추는 버그
- **문제**: 허용 오차 밖인데 정렬이 끝나 위치가 어긋남
- **원인**: 비례 제어 속도가 목표 근처에서 최소 유효 속도 미만으로 떨어지면 "움직일 필요 없음"으로 판단
- **해결**: 허용 오차 밖이면 최소 속도를 보장

### ⑥ 미션 순서 인식 (추측·복원)
- **문제**: 블록 하나를 놓치면 옆 블록이 그 자리로 당겨져 순서 전체가 틀림. 화면 끝·보라·주황을 자주 놓침
- **원인**: "보이는 블록을 왼쪽부터 3개" 고르는 방식이라 빠진 자리를 알 수 없음
- **해결**
  1. 카메라 자세가 고정이므로 6자리마다 화면 좌표 범위를 정해 블록이 자기 자리에서만 인정되게 함 (빈자리는 0, 다른 자리 안 밀림)
  2. 규정상 미리 공개되는 **배정표(색 구성)**를 이용해 못 읽은 자리를 남은 색으로 복원
  3. 자리마다 감지 횟수(hits)와 가장 많이 보인 색(weak)을 따로 세어 "색 미확정 자리"와 "진짜 빈자리"를 구분, 약하게라도 보인 색을 우선 배정
  4. 같은 색이 배정표보다 많이 읽히면 득표가 가장 적은 자리를 비우고 다시 배정 (빨강↔주황 오인식 대응)
  5. 높이가 작은 조각(반사로 쪼개진 색)은 무시
- **결과**: 시험 6판 중 5판 정답. 1개 누락은 항상 정답으로 복원. 확정/추측 여부를 `final:` / `guess:`로 출력

### ⑦ 팔을 돌리며 연속 촬영하는 순서 인식 (시제품)
- **아이디어**: 고정 사진 2장 대신 밑동(j1)을 천천히 돌리며 연속 촬영. 화면 x와 j1 각도를 합친 위치(`u = x + 0.64 × j1`)로 같은 블록을 묶어 왼쪽부터 정렬
- **근거 측정**: j1을 50씩 돌리며 블록 x가 약 −32px씩 일정하게 이동함을 확인, 블록별 보정 위치가 ±3~5로 모임
- **장점**: 로봇 위치가 밀려도 블록끼리 순서는 유지, 같은 색 중복도 위치로 구분, 간격으로 빈자리 감지
- **상태**: T40에 구현(스위치로 켜고 끔), 대회에는 자리별 범위 방식 사용

### ⑧ 적재함 탐색·집기
- **문제**: 빨강을 찾으라 했는데 위층 노랑을 집고, 중심이 어긋남
- **원인**: 모든 층이 같은 화면 범위를 써서 위층 자세에서 아래층 블록이 보임. 카메라 중심 기준이 이전 로봇 값
- **해결**: 층별 화면을 실측해 세로 범위를 좁힘(y 52~145), 층마다 중심 x 재측정, 블록 x 오차만큼 옆으로 이동 후 집기. 탐색 중 본 블록 위치를 칸별로 기억해 다음 블록은 바로 그 칸으로 이동, 탐색은 지금 열부터 시작
- **결과**: 열 이동 오차가 있어도 안정적으로 집음, 재탐색 시간 감소

### ⑨ 조명에 따른 색 인식
- **문제**: 인식 존에서 빨강을 맞추면 적재함에서 못 찾고, 반대도 마찬가지. 화면 끝 블록은 램프를 켠 직후에만 보임
- **원인**: Pixy는 각 화소를 가장 가까운 색 번호 하나에만 배정 → 적재함 조명에서는 주황 범위가 빨강을 먼저 가져감. 화면 끝은 카메라 자동 노출이 밝기를 다시 낮추면서 색 범위를 벗어남
- **해결**: 남는 signature 7을 다른 장소용 색으로 쓰는 기능(`SIG7_COLOR`), 찾는 색마다 램프를 켜고 끄는 표(`STORAGE_LAMP_FOR_COLOR`), 자동 노출·화이트밸런스 고정 절차 정리
- **결과**: 장소별 조명 차이에 대응할 수단 확보 (최종 경기는 램프 전부 켬으로 운용)

### ⑩ Zone B 복귀 시간 단축과 위치 정확도
- **문제**: B에서 돌아올 때 매번 1열까지 왕복해 시간 손실. 2열로 바로 오게 하자 2·3열 사이에 서는 일이 잦음
- **원인**: 회전 2번 + 고정 거리만으로 위치가 정해짐. 회전 후 측면 PSD 정렬은 한 열(70mm)을 제한 시간 안에 못 움직임. 돌기 전 전방 PSD 하나만 쓴 시도는 보는 면이 섞여 4열로 감
- **해결**: 회전 직전(Zone A 쪽을 볼 때) 전방 PSD **평균 + 좌우 차**로 열 위치와 비틀림, 우측 PSD로 적재함 거리를 먼저 맞춤. ±20mm에서 값이 고르게 변하는지(약 0.7/mm, 좌우 차 −50으로 일정) 확인 후 기준으로 채택. 회전 후에는 앞뒤 거리와 비틀림만 다시 맞추고 2열부터 탐색(2 → 3 → 4 → 3 → 2 → 1)
- **결과**: B 복귀마다 1열 왕복 제거

### ⑪ 경기 시간 줄이기
- 구간별 경과 시간 출력(`[T] obstacle +4.8s total 4.8s` 형식)으로 병목을 찾음
- 대회 당일: 이동 속도 140 → 170, 탐색 이동 120 → 160, B 이동 회전·주행 150으로 상향, 팔 대기 시간 조정

## 4. 운영에서 배운 점

- **배터리 전압이 변수**: 9V 근처에서 이동 시간 초과, 미끄러짐, 정렬 미완료가 함께 발생. 시험·튜닝은 11.5V 이상에서만
- **센서는 검증 후 신뢰**: PSD는 거리별 민감도가 다르고, 보는 면이 바뀌면 값이 튐
- **"보인다"와 "찾았다"는 다르다**: PixyMon에 라벨이 떠도 코드의 화면 범위·최소 장수 조건에 걸리면 찾지 못함. 범위 값 오타 한 줄이 전체 실패를 만든 사례를 겪고, 시험 출력에 판단 근거(IN/out, hits, weak)를 항상 함께 찍도록 함
